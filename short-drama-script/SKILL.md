# 短剧场次本写作与项目标准

默认采用**纯场次本**，一场＝一个连续时空。创作者要求把导演手法、镜头运动和表演写进单集、
让制作者只读该集时，使用**导演执行整合稿**；在全局设定登记 `剧本格式：导演执行整合稿`。
未选择整合模式的旧项目保持原格式。两种模式都用一份单集正本，具体区别见格式标准§0.1。
格式定义见 [references/format-spec.md](references/format-spec.md)——写任何一集之前先按它对齐。

写作与审查是两个工作单元：**写作轮**产出与修改正本及派生件；**审查轮**交给
`$short-drama-script-audit`。写手不给自己签字。

## 一、先把项目建对

完整目录树、七份文档的职责与命名、别名规则，见
[references/project-layout.md](references/project-layout.md)。要点：

```text
<项目目录>/
|-- 第N集.txt                      正本：一集一文件，纯剧本格式
|-- <剧名>-全局设定.txt             画风／光色／格式规范／世界观／资产命名表／人物／场景／物品／出图提示词
|-- <剧名>-第一季整体大纲.txt        故事引擎／人物弧线／分集地图／集间衔接硬规则／逐日锚点
|-- <剧名>-台词对照本.txt           逐条英文＋中文大意（对账与配音用）
|-- <剧名>-分集场次表.txt           一行一场：排期与资产分派用
|-- 交付/                          打包 zip 与 PDF 的落点
|-- 审查/                          所有审查记录（第 N 轮、机械校验 json）
`-- 备份-<节点>-<YYYYMMDD>/        改稿前快照（改稿前先拷一份）
```

## 二、工作流

1. **新建项目**

   `python3 scripts/init_project.py <项目目录> --title <剧名> --episodes <N>`

   生成目录骨架 ＋ 四份支持文档 ＋ 第一集集头模板。已存在的文件一律跳过、不覆盖。

2. **写一集**：读 [references/format-spec.md](references/format-spec.md) 与
   [references/write-checklist.md](references/write-checklist.md)，然后写 `第N集.txt`。
   写之前先把这一集的数值／道具／伤情／时间账对齐整体大纲。
   每集写完按 [references/dramatic-momentum.md](references/dramatic-momentum.md) 做推进自检：检查开场正在发生的压力、
   改变策略的升级、选择后果、行动中的关系变化与结尾未结问题。不要用增加运镜或微表情代替改戏。
   写完或补写摄影、微表情、VO后，按 [接缝与动作顺序](references/continuity-seams.md) 重读整场动作链及相邻接缝；
   把补充说明嵌回原动作，不在已完成的动作后再演一遍。机械校验和派生件一致不能代替此项。

3. **生成派生件**（不许手写、不许手改）

   `python3 scripts/build_derived_docs.py <项目目录>`　重建分集场次表＋对账台词对照本

   `python3 scripts/build_derived_docs.py <项目目录> --check`　只报差异，不动文件

   台词对照本的中文由已有稿保留、新句补齐；脚本会列出缺中文的条目。
   分集场次表的"物件"列从《全局设定》的 `PR-xx` 表取名（也认资产名里"的"后面的那个词，
   例：`后补的碗` 认 `碗`）；没有《全局设定》时才退回通用兜底词，别指望它识别你的专有道具。
   PR 名尽量写剧本里实际出现的词，名字越贴近台词，这张表越准。

   `python3 scripts/estimate_duration.py <第N集.txt> --spec 90`　时长自查

   报告这一集的正文/对白字数、可演动作条数、逐场并行折算与预计成片秒数。
   此字符拟合只用于纯场次本。导演执行整合稿以场次预算、对白试读和动作预演判断，
   不把摄影说明或表演括号字数当作新增片长。时长口径见 [references/timing-model.md](references/timing-model.md)；
   **先在《全局设定》里写一行 `成片规格：单集 N 秒`**，审查脚本才会逐集校验篇幅。

4. **自查门禁**：跑 `$short-drama-script-audit` 的
   `scripts/audit_plain_script.py <项目目录>`。FAIL 不为 0 不要往下走。

5. **交审查**：审查记录落 `审查/`，按 `$short-drama-script-audit` 的
   `references/review-ledger.md` 写。
   默认每完成连续三集，再做一次 [三集联合回归](references/three-episode-review.md)：
   连读台词、剧情走向、钩子兑现、回报与节奏、连续性及支持文档，并接住下一集入口。
   创作者可调整频率；三集节点不替代单集自检，不强加每三集相同的剧情高潮。

6. **按需生成全集 TXT**：用户要求“合并全集／去掉分集概要／只留第N集正文”时，
   采用 [project-layout.md §5.1](references/project-layout.md) 的清洁阅读版；顶部只放一次全剧概要与人物说明一览。
   使用 `scripts/build_complete_script.py`，不删改单集正本的概要块，不手工拼接派生全集。
   制作不可缺少的条件先落入各集对应场内，不能只留在会被剥离的制作前言中。

7. **交付**：`python3 scripts/pack_delivery.py <项目目录> --label r1`

   包内结构、UTF-8 文件名、逐文件字节校验、SHA-256 由脚本负责；已存在的同名包不覆盖，自动加序号。

## 三、写作硬约束

下面几条直接决定返工量，其余见 format-spec。

1. 集头区分三层，顺序固定：**文档头**（第一行只写 `<剧名> · <英文名>`，不带集号）→
   **概要块**（本集概要 → 【本集大场面】→ 本集人物 → 本集场景）→ **集头块**
   （`第 N 集：<集名>` ＋ 语言声明行）。老排法用 `migrate_header.py` 迁过来。
2. 场标题只允许 `【N-M 时间 内／外 场景】`；时间只用 `日／昏／夜／晨` 四个词；
   切空间就换场号。**一场＝一个连续时空**：时间从夜走到晨、或中途换了地点，都要拆成两场。
3. 同一母场景必须带子视图（`干涸航道·沙脊`）。只写母场景名，等于让分镜把同一套景重复生成几十次。
4. 人物行只写资产命名表里的英文人名，或已登记的群像。不写中文注释、不写分号；载具不是人，不进人物行。
5. 说明文字（概要、大场面、动作行、语气提示）不出现“他／她”，一律用人名——分镜与人物识别靠名字。
6. 普通现场对白不加标记；现场人物不在画面中才标 `[OS]`，提示写明“画外对白”和位置。内心独白、旁白等非现场叠加声标 `[VO]`，提示明确写“内心独白”或具体旁白类型，不能只写缩写（详见 format-spec §5）。
7. 台词是目标语言原句、人名保持英文；动作、语气提示、概要保持中文。一个项目只允许一种台词语种。
   对白写作 `角色（可观察的表演反应、发声策略）：目标语言台词`；微表情、视线、呼吸与身体反应
   按当前触发选择，不堆成每句固定套餐。完整动作放在相邻△行，声源分类保持正确，见格式标准§4.1。
8. 画面里不出现任何可读文字（旗号只用图形，不做字幕与水印）。
9. 单集时长以创作者与项目规格为准；场数与台词量按冲突规模和可执行动作定，不为模板时长凑戏。

9. **台词工程**见 format-spec §6.5：先定口径（国内竖屏＝每集 2–3 句金句预算；海外／电影级＝禁止金句），
   再按标点节奏表、单句长度上限（中文 ≤35 字／英文 ≤62 字符）、内心独白（VO）密度（二选一写进《全局设定》）
   过一遍。集尾钩子不许落在空镜上。

## 四、派生文件不许手改

`分集场次表`、`台词对照本`、按需交付的`全集 TXT`、`交付包`一律由脚本生成。改了正本就必须重跑
`build_derived_docs.py`；已有全集时还须重跑 `build_complete_script.py` 并用 `--check` 比对。派生件与正本脱钩是这套流程里最常见的翻车点，
审查脚本会按“条数＋正文”逐条对账。

## 五、与其它 skill 的关系

- 审查：`$short-drama-script-audit`——同一份格式标准的另一端。
- 本 skill 的 `references/format-spec.md`、`references/project-layout.md` 与审查 skill 里的
  同名文件是**同源副本**，文件头有「同步源」行；改一处必须同步另一处，审查脚本会做 hash 比对。
- 导演执行整合稿可直接写摄影与表演执行意图；逐镜生成单元、关键帧及媒体交对应制作技能。

## 六、维护（改完必须推仓库）

本 skill 与 `$short-drama-script-audit` 同属仓库 `beautyaiClub/short-drama-skills`（GitHub）。
**任何改动——改 SKILL.md、加 references、改脚本——都要 commit 并 push 到该仓库**，
不要只改本地安装副本。仓库根目录有 `sync.sh`，用来在「仓库」与 `~/.codex/skills` 之间对齐：

```bash
./sync.sh              # 仓库 → ~/.codex/skills（装最新版）
./sync.sh --check      # 只比对差异，不动文件
```

改完的固定顺序：改仓库里的文件 → `./sync.sh` → 跑校验（脚本自测 ＋ 真项目体检）→ commit ＋ push。
