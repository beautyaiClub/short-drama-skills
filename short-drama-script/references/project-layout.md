# 项目结构标准

这套结构的目标是：**任何人拿到项目目录，不用问就能开工**——正本在哪、资产怎么命名、
派生件怎么来的、审查走到第几轮、交付包是哪一个。

## 1. 目录树

```text
<项目目录>/
|-- 第N集.txt                        正本（一集一文件，纯剧本格式）
|-- <剧名>-全局设定.txt               画风／光色／世界规则／资产命名表／人物／场景／物品／出图提示词
|-- <剧名>-第一季整体大纲.txt          故事引擎／人物弧线／分集地图／集间衔接硬规则／逐日锚点
|-- <剧名>-台词对照本.txt             逐条英文＋中文大意（对账与配音用）
|-- <剧名>-分集场次表.txt             一行一场：排期与资产分派用（脚本生成）
|-- <剧名>-台词中文映射.txt           （可选）新增／改写台词的中文补充表：`集号｜EN｜CN`
|-- <剧名>-交付说明.txt               （可选）包内有什么、怎么用、本轮改了什么
|-- 交付/                            所有对外交付物：zip、PDF
|   `-- 旧版本/
|-- 审查/                            所有审查记录：第 N 轮 md ＋ 机械校验 json
|-- 备份-<节点>-<YYYYMMDD>/           改稿前快照
`-- 项目开发/                         （可选）选题、决策、制作形态卡等过程文件
```

## 2. 七份文档的职责

| 文件 | 一句话职责 | 最小内容 | 谁读它 |
|---|---|---|---|
| 第N集.txt | 这一集的可拍剧本 | 集头块 ＋ 场标题 ＋ 人物行/`△`动作行/对白行 | 分镜、资产、配音、演员 |
| 全局设定 | 全剧共用的唯一契约 | 画风与光色、格式规范、世界观、**资产命名表（S/CH/PR）**、人物卡、场景卡、物品卡、出图提示词 | 美术、资产、分镜、写手 |
| 整体大纲 | 这一季为什么这么排 | 故事引擎、三条人物弧线、副线（如资源线）、逐集地图、**逐日时间锚点**、集间衔接硬规则、伏笔优先级 | 统筹、写手、审稿 |
| 台词对照本 | 台词账 | 与正本一一对应的 `EN｜` / `CN｜`，含场标 | 配音、审稿、翻译 |
| 分集场次表 | 排期与分派表 | 总览（每集场数/台词数/时间分布）、场景使用统计、逐集一行一场（场号｜时间内外｜场景｜人物｜物件｜台词数） | 统筹、资产、分镜 |
| 交付说明 | 这一包是什么 | 包内清单、版本与日期、本轮改动、已知待办 | 客户、审查员 |
| 审查记录 | 审到哪一步 | 第 N 轮记录（范围/依据/机械校验结果/结论/逐条 finding 与状态） | 写手、客户 |

## 3. 命名与别名规则

- 支持文档一律 `<剧名>-<类型>.txt`；剧名取自正本第一行 `<剧名> · <英文名> · 第 N 集：…`。
- 脚本探测支持别名：`分集场次表`／`分集表`；`台词对照本`／`对照本`。两个脚本都按别名找文件，
  找到哪个用哪个，找不到就报缺。
- **正本文件名固定** `第N集.txt`（中文数字），因为分镜系统按文件名排序取集号。
- 台词对照本可以暂缺（早期项目），但一旦有配音或跨语言需求就必须补齐；
  分集场次表随时可由正本重建，不该手工维护。

## 4. 资产命名表（写进全局设定，是全剧的命名契约）

三条铁律，写在全局设定里并由审查脚本校验：

1. 一个资产只提交一次：同一个人／场景／物品，全季只有一个 ID、一个正式名称。
   其他叫法都是别名，必须映射回同一个 ID（例：`CH-01 Kane｜别名：机械师`）。
2. 状态变化算同一资产的变体：车被打废、闸门被撞倒、水塔被打穿、掉了一只鞋——
   都是同一 ID 下的 state，不新建资产。
3. 剧本场标题写「正式名（＋子视图）」：`山谷营地·水塔下`——ID 只活在资产命名表里
   （`S2 山谷营地｜子视图：营地中央 / 篝火边 / 水塔下…`）。唯一的例外是载具：
   它跨集复用、状态多变，取景也要带 ID，写 `PR-01 巨车·货舱` 这种形式。

群像与发声标签分开管理：无名角色归一个群像资产（`CH-xx 营地女战士群像`）；
需要开口的无名角色用固定标签表（`掠夺者甲`／`护卫`／`杀手`…），**标签只用于对白行，不写进人物行**。

## 5. 交付目录（交付/）

放**所有对外交付物**：打包 zip、导出的 PDF（概要、审查记录、台词本）。

- 命名：`<剧名>-<范围>-<YYYYMMDD>[-<标签>].zip`，例如 `狂沙-WASTELAND-第一季-全12集-20260924-r2.zip`。
- 打包用 `scripts/pack_delivery.py`：显式写 UTF-8 文件名标记（macOS 的 `zip` 默认不打，解压会乱码）、
  写入后逐文件回读比对字节、输出 SHA-256。
- 旧包不覆盖：脚本自动加 `-r2` 一类序号；要留档就留在 `交付/旧版本/`。

## 6. 审查目录（审查/）

放**所有审查记录**，命名与内容按 `$short-drama-script-audit` 的 `references/review-ledger.md`：

```text
审查/
|-- 全季-审查-第1轮.md            首审（全量）
|-- 全季-审查-第2轮.md            复审（只审上一轮 FAIL 原位置＋波及范围＋回退检查）
|-- EP07-审查-第1轮.md            单集专项（可选）
|-- 机械校验-第1轮.json            脚本输出（可作为门禁凭据）
`-- 机械校验-第2轮.json
```

**每次审查一个新文件，不覆盖旧记录**——这是“改了什么、审到哪一步”能追溯的前提。

## 7. 备份约定

动大手术之前先整份拷一份：`备份-<节点>-<YYYYMMDD>/`（例：`备份-审查前-20260921/`、
`备份-整改前-20260924/`）。旧格式剧本、旧版派生件也各留一个目录（`旧格式备份/`），
便于回溯与对账。不做就地覆盖。
