# 审查记录规范

审查轮只出结论，编辑轮才动源文件。两者分开，是为了让"改了什么"永远可追溯。

## 1. 落在哪

```text
项目目录/
`-- 审查/
    |-- 全季-审查-第1轮.md        ← 首审（全量）
    |-- 全季-审查-第2轮.md        ← 复审（只审受影响范围 + 回退检查）
    `-- EP07-审查-第1轮.md        ← 单集专项（可选）
```

每次审查一个新文件，不覆盖旧记录。

## 2. 文件头

```markdown
# <剧名> 剧本审查 · 第 N 轮

- 范围：全 12 集 / 仅 EP07–EP09（复审）
- 依据：《<剧名>-全局设定.txt》资产命名表 + 本技能 format-spec / audit-checklist
- 机械校验：`python3 scripts/audit_plain_script.py <项目>`
  - 结果：场 130 ｜ 台词 1557 句 ｜ FAIL 0 ｜ WARN 19
- 结论：`APPROVE_WITH_NOTES`
```

## 3. finding 一行一条

| 编号 | 级别 | 类别 | 位置 | 证据（原文） | 影响 | 修法 | 状态 |
|---|---|---|---|---|---|---|---|
| F-012 | FAIL | 连续性·数值 | EP09 · 9-6 | 文里报"108 支箭"，前一场报"200 支" | 观众可数出错 | 统一为 108，并同步大纲 | closed |
| F-013 | WARN | 接缝 | EP05 · 5-3 | 上一场黄昏、这一场夜，开场无时间线索 | 成片硬切 | 开场补"天刚黑透" | closed |

字段口径：

- **级别**：`FAIL`（阻断，必须改）／`WARN`（建议，可不改）／`INFO`（记录，供决策）。
- **类别**：用 [audit-checklist.md](audit-checklist.md) 的分类编号（A 格式 / B 连续性 / C 接缝 / D 台词）。
- **位置**：`EPnn · 场号`（有行号更好）。
- **证据**：**必须引原文**，不许只写"感觉不对"。
- **影响**：说明它到制作端会变成什么（分镜读错／配音错口型／硬切／返工）。

## 4. 状态机

```text
open → acked → fixed → verified → closed
                 └────────────────→ wontfix（必须写明理由）
```

- `open`：已提出，未处理。
- `fixed`：源文件已改；**复审时逐条回到文件里确认**，不能只信"改过了"。
- `verified`：复审在原位置核对通过，且**上一轮已关闭项没有回退**。
- `wontfix`：创作者明确不改；理由写进记录（品味项只能落这里）。

## 5. 轮次纪律

- **首审**：全量跑机械项 + 四类专项（格式／连续性／接缝／台词）。
- **复审**：只审①上一轮 FAIL 的原位置、②改动波及范围、③上一轮 closed 项是否回退。
  没有新证据不重复已关闭项。
- **改动波及范围**怎么定：改了台词 → 上下各两句重读；改了场景 → 本场与相邻两场；
  改了时间 → 本集全部接缝 + 跨集接缝。

## 6. 结论分级（写进每个审查文件的头部）

- `APPROVE`：无阻断问题，可进下一步。
- `APPROVE_WITH_NOTES`：只有不阻断的改进。
- `REVISE`：存在 A/B/C/D 任一类的实质问题。
- `PROVISIONAL`：关键输入缺失（没有资产表／没有台词账／只有片段），无法完成判断。

交付要分两层给结论：**内容层**（正本能不能进下一步）与**包层**（这个文件夹能不能直接发出去）。

## 7. 汇报口径

给用户的文字按这个顺序：

1. 一句话结论（能不能往下走）。
2. 按类分组的发现，每条 = 证据 + 影响 + 修法；机械项附脚本输出。
3. 改与不改的分界：哪些必须改，哪些只是建议；品味问题单独列。

不要把概率性的"可能有问题"写成 FAIL；不确定的写 WARN 并说明需要什么证据才能定级。
