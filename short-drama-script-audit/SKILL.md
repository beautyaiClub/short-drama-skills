# 纯剧本格式审查与规约

目标格式是**纯剧本格式（场次本）**：剧本只管戏，一场＝一个连续时空，
镜号／机位／时长那一层全部交给分镜系统。格式定义见
[format-spec.md](references/format-spec.md)——审查前先按它对齐，否则结论没有共同基准。

审查与修改是两个工作单元：**审查轮只出结论，用户明确要求时才进编辑轮。**

本 skill 的 `references/format-spec.md`、`references/project-layout.md` 与写作 skill
`$short-drama-script` 里的同名文件**逐字节同源**；改一处必须同步另一处（脚本会做 hash 比对）。

## 用法

1. **冻结范围**：审哪几集、哪些文件、第几轮、用户已明确的限制。
2. **跑机械校验**（先做，不要手算）：

   ```bash
   python3 scripts/audit_plain_script.py <项目目录>
   python3 scripts/audit_plain_script.py <项目目录> --json 审查/机械校验.json
   ```

   脚本查的是 [audit-checklist.md](references/audit-checklist.md) 里标 `[机]` 的那些：
   集头块、场标题的时间／内外／场号／子视图、人物行写法、说话人是否在人物行、
   载具有没有混进人物行、场外声缺 `[VO]`、旧格式字段残留、说明文字里的"他／她"、
   夜戏缺光源、时间变化接缝缺时间承载、同集台词复用、台词量、**台词对照本与正本逐条对账**，
   以及项目层：支持文档齐不齐、**分集场次表有没有与正本脱钩**、审查记录与交付包是不是过期。
   有 FAIL 时退出码为 1，可以直接当门禁。
3. **逐场通读**：机械项过了再读内容。按 [audit-checklist.md](references/audit-checklist.md)
   B／C／D 三类逐场过——连续性、接缝、台词，这三类只能读出来。
4. **写审查记录**：按 [review-ledger.md](references/review-ledger.md) 落盘到 `审查/`，
   一行一条 finding，必须带原文证据与影响。
5. **收口**：复审只审①上一轮 FAIL 的原位置、②改动波及范围、③已关闭项有没有回退。

## 项目结构假设

```text
项目目录/
|-- 第N集.txt                   正本（纯剧本格式，含集头块）
|-- <剧名>-全局设定.txt          画风/光色/格式规范/硬规则/资产命名表/人物/场景/物品/出图提示词
|-- <剧名>-第一季整体大纲.txt     故事引擎/人物弧线/分集地图/制作提示
|-- <剧名>-台词对照本.txt         逐条英文＋中文大意，用于对账与配音
|-- <剧名>-分集场次表.txt         每集：概要块 → 集标题 → 一场一行的场景表（排期与资产分派用）
|-- 交付/                       打包 zip 与 PDF 的落点
`-- 审查/                       本技能产出的审查记录（每次审查一个新文件，不覆盖）
```

目录树、七份文档的职责与命名、别名规则（`分集表`＝`分集场次表` 等）见
[project-layout.md](references/project-layout.md)。命名不同先适配，但
"正本＋共用设定＋可对账的台词账"三件事必须成立，否则只能给 `PROVISIONAL`。

## 五类审查

| 类 | 查什么 | 手段 |
|---|---|---|
| A 格式与可解析性 | 集头块、场标题（时间／内外／子视图）、人物行、`[VO]`、旧字段残留、台词账对账 | 脚本 + 少量阅读 |
| B 连续性 | 数值线、道具线、伤情线、时间线、信息线、道具来源 | 逐场阅读，画时间轴／状态表 |
| C 接缝与顺滑度 | 本场落地、下一场接住、时间承载、到场交代、战斗收束、夜戏光源、集间接续 | 逐接缝读"上一场末句＋下一场首句" |
| D 台词 | 金句腔、翻译腔、复用、改词后的接话断裂、与动作矛盾、腔调雷同 | 逐场朗读，按角色统计句长 |
| P 项目与交付 | 支持文档齐不齐、派生件与正本是否脱钩、审查记录有没有留档、交付包是否比正本旧 | 脚本 + 目录核对 |

每条的具体"症状／怎么查／怎么修"，以及我们一路踩过的真实例子，都在
[audit-checklist.md](references/audit-checklist.md)。

## 三条必须守住的审查纪律

1. **对账要比台词正文**，只比说话人不算查过。
2. **扫正文要含续行**：换行后的动作描述同样是人名与光源的载体，只扫 `△` 开头的行会漏检。
3. **改动按集定位**：补丁或替换若按"整句"全局查找，遇到跨集重复句会改错行。

这三条是工具层的坑，不是作者的问题；但它们会直接产出错误结论，所以写在清单 E 类里。

## 结论分级

- `APPROVE`：机械项全过，四类专项都有证据支撑、无阻断问题。
- `APPROVE_WITH_NOTES`：只有不阻断的改进。
- `REVISE`：存在 A／B／C／D 任一类的实质问题。
- `PROVISIONAL`：缺关键输入，无法完成判断。

交付问题分开给结论：**内容层**（正本能不能进下一步）与**包层**（这个文件夹能不能直接发出去）。

## 边界

- 不替 owner 改来源文件；用户要求修改时只改必要项，并在回复里列出改了什么、动了哪些文件。
- 不产出分镜、关键帧、图片、视频、配音、音乐；发现的问题指向剧本层或其他 owner。
- 没看过媒体时，不对表演、口型、混音、调色、平台合规背书。
- 品味与创作选择（气质、节奏、金句偏好）不得单独判为缺陷，只能作为 `taste_option`／`warnfix` 记录。
- 概率性的怀疑不写 FAIL；写 WARN 并说明还缺什么证据才能定级。

## 维护（改完必须推仓库）

本 skill 与 `$short-drama-script` 同属仓库 `beautyaiClub/short-drama-skills`（GitHub）。
**任何改动——改 SKILL.md、加 references、改脚本——都要 commit 并 push 到该仓库**，
不要只改本地安装副本。仓库根目录有 `sync.sh`，用来在「仓库」与 `~/.codex/skills` 之间对齐：

```bash
./sync.sh              # 仓库 → ~/.codex/skills（装最新版）
./sync.sh --check      # 只比对差异，不动文件
```

两份与写作 skill 同源的 `references/format-spec.md`、`references/project-layout.md` 必须一起改；
脚本会做 hash 比对，漂移会在 P 类检查里报出来。
