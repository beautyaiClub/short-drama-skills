# short-drama-skills

两个 Codex skill，构成短剧剧本「写 → 审 → 交」的标准闭环：

| skill | 职责 | 入口 |
|---|---|---|
| `short-drama-script` | 写纯剧本格式（场次本）剧本；维护项目骨架（全局设定／整体大纲／台词对照本／分集场次表）；生成派生件；打包交付 | `SKILL.md` |
| `short-drama-script-audit` | 审查同一格式的剧本：机械校验、连续性、接缝、台词、项目与交付层；出审查记录与结论 | `SKILL.md` |

两边的 `references/format-spec.md`、`references/project-layout.md` 是**逐字节同源副本**，
改一处必须改两处；审查脚本会做 hash 比对，漂移会在检查里报出来。

## 剧本格式：纯剧本格式（场次本）

> **权威定义**：`short-drama-script/references/format-spec.md`（与
> `short-drama-script-audit/references/format-spec.md` 逐字节同源）。本章是面向读者的完整说明，
> 规则与它一致；改格式要三处一起改，见 [维护规则](#维护规则)。
> 本章示例是虚构教学样例；`format-spec.md` 里的样例取自实际项目。

### 1. 设计原则

一句话：**剧本只管“戏”**。

- 一场 = 一个连续时空。场里只有三样东西：人物行、`△` 动作行、对白行。
- 镜号、景别参数、机位、焦段、运镜参数、每场时长、集内镜数、场次表——**一律不写**，那是分镜层的活。
- 格式必须能被机器稳定解析：分镜与配音系统靠“场标题 ＋ 人物行 ＋ `[VO]` ＋ 说话人”判断时空、
  站位与口型。这几处写歪，后面全线返工。
- 剧本要能当“施工图”读：动作写看得见、听得见的东西，并且每一下都有明确的结束状态。

### 2. 文件与命名

| 项 | 规定 |
|---|---|
| 文件格式 | 纯文本 `.txt`，UTF-8，无 BOM，无 Markdown 标记 |
| 一集一文件 | `第N集.txt`，N 用中文数字：`第一集.txt`、`第十一集.txt` |
| 语言分工 | **台词**用目标语言原句、**人名保持英文**；动作、语气提示、概要用中文 |
| 派生件 | 台词对照本、分集场次表由脚本生成，不手写、不手改 |

### 3. 集头块（顺序固定，不能乱）

```text
<剧名> · <英文名> · 第 N 集：<集名>
(人物名称英文 · 台词英文；场景、动作与语气提示为中文)

本集概要：<3–6 句中文；说明文字不出现“他／她”，一律用人名>
【本集大场面】
· <场号范围> <大场面名>：必须看到什么（规模与比例参照、物理后果；不写运镜）
· …
本集人物：<主角 → 群像 → 反派；这一集出现过的全部人物>
本集场景：<这一集用到的全部场景，写到子视图>
```

| 块 | 写什么 | 容易踩的坑 |
|---|---|---|
| 标题行 | 剧名 · 英文名 · 第 N 集：集名 | 脚本与打包靠这行取剧名／英文名，缺英文名包名会退化成只带中文名 |
| 语言声明行 | 一行说清语言分工 | 别在这里写时长、镜数、语言以外的参数 |
| 本集概要 | 这一集发生了什么的账 | 出现“他／她”会让分镜认错人 |
| 【本集大场面】 | 3–5 条“必须看到什么” | 写体量差、物理后果、比例参照；**不写机位与运镜** |
| 本集人物 | 这一集出现过的全部人物 | 顺序：主角 → 群像 → 反派；载具不写进来 |
| 本集场景 | 这一集用到的全部场景 | 写到子视图那一级，便于资产分派 |

### 4. 场标题

```text
【N-M 时间 内／外 场景】
```

| 字段 | 允许值 | 说明 |
|---|---|---|
| `N-M` | 集号-场号 | 场号从 1 连续；**切空间就换场号**，同一空间连续算一场 |
| 时间 | `日`／`昏`／`夜`／`晨` | 封闭集合，是分光与调色的开关。`清晨`、`深夜`、`夜／晨` 这类自造写法一律不合格 |
| 内／外 | `内`／`外` | 只有这两个值 |
| 场景 | 资产规范名（＋子视图） | 同一母场景必须带子视图：`干涸航道·沙脊`；载具取景写 `PR-01 拖船·驾驶舱` |

**为什么子视图是硬要求**：只写母场景名，分镜会把同一套景重复生成几十次——这是“场景看起来单调”的第一原因。

**为什么“一场＝一个连续时空”**：时间从夜走到晨、或中途换了地点，都要拆成两场。
揉在一场里，布光与调色没有依据，接缝一定会硬。

### 5. 场下三件套

```text
人物：<资产命名表里的英文人名、顿号分隔>

△（景别）<动作……>

<角色名>（<语气或策略提示>）：<台词原句>
```

| 行 | 规定 | 反例 |
|---|---|---|
| 人物行 | 只写资产命名表里的英文人名，或已登记的群像名（`塔楼守卫群像`）；顿号分隔 | `Rune（拖船内）、Lena`（带中文注释）、`拖船、Rune`（载具不是人）、用分号分隔 |
| 动作行 | 以 `△` 开头，一行一个动作节拍，只写看得见听得见的东西；括号里只给景别，必要时加**一个**运镜词 | `△（近景·推轨 24mm）`（写了机位与器材）、`△ Rune 转身。`（没有结束状态） |
| 对白行 | `角色名（语气提示）：台词` | 把语气提示写成台词的一部分；同一场里台词语种混用 |

景别用词：`远景`／`中景`／`近景`／`特写`／`快切`；运镜词只在必要时加一个，如 `（近景·推）`。

### 6. 场外声与语气提示

- **场外人声必须标 `[VO]`**：无线电、电台、录音、喇叭、电话、从画外／远处传来的声音。
  漏标的后果是配音阶段把它当现场口型处理。
- 语气提示写在角色名后的括号里、用中文，例：`Lena（压低，短，不带情绪）：…`。
  它是给配音与表演的开关，不是台词的一部分。
- 说明文字（概要、大场面、动作行、语气提示）里**不出现“他／她”**，一律用人名。

### 7. 命名与资产

资产命名表写在《全局设定》里，是全剧的命名契约：

1. 一个资产只提交一次：同一个人／场景／物品，全季只有一个 ID、一个正式名称；其他叫法都是别名
   （例：`CH-01 Rune｜别名：船长`）。
2. 状态变化算同一资产的变体：车被打废、闸门被撞倒、水塔被打穿、掉了一只鞋——都是同一 ID 下的 state。
3. 剧本场标题写「正式名（＋子视图）」：`干涸航道·沙脊`。ID 只活在资产命名表里；
   唯一的例外是载具——它跨集复用、状态多变，取景也要带 ID：`PR-01 拖船·驾驶舱`。

群像与发声标签分开管理：无名角色归一个群像资产；需要开口的无名角色用固定标签
（`掠夺者甲`／`护卫`／`杀手`…），**标签只出现在对白行，不写进人物行**。

### 8. 长度与节奏口径

参考量（来自一季 12 集、每集约 11 分钟的成片项目）：

| 项 | 量级 |
|---|---|
| 单集场数 | 9–15 场 |
| 单集台词 | 100–200 句 |
| 单集篇幅 | 非空白 7,000–11,000 字（含英文台词，文件约 15–20 KB） |
| 夜戏比例 | 全季 ≤30% |

集间硬规则：**每一集结尾的最后一个动作或最后一句台词，必须是下一集开场的直接原因**。
如果一集结尾删掉、下一集照样能开场，这个结尾就不算数，要重写。

### 9. 禁止项

出现任意一条即格式不合格：

`镜号`／`景别：`／`机位`／`焦段`／`时长：`／`画面：`／`声音：`／`衔接：`／`运镜：`／
`场次表`／`生成单元`／`本场时空气氛`／`镜头纪律例外`／场标题里的时间自造词／
人物行里的中文注释或分号／画面里出现可读文字（旗号只用图形，不做字幕与水印）。

### 10. 完整样例（虚构教学样例）

```text
寂海 · SILENT SEA · 第 1 集：退潮
(人物名称英文 · 台词英文；场景、动作与语气提示为中文)

本集概要：退潮时分，Rune 的拖船被困在干涸的航道里，远处灯塔的探照灯扫过船身。
Lena 带着两个人从沙脊上下来，要用三桶淡水换船上的绞盘；Rune 答应修好绞盘，
但不肯交出船舱钥匙。夜里潮水回来，两边一起把船拖出沙脊。

【本集大场面】
· 1-2～1-4 拖船搁浅：船体比人高出三个身位，龙骨陷进沙里，涨潮时整条航道的水一次涌上来。
· 1-6 绞盘拉船：两根钢索绷成直线，把船从沙脊上硬拖回水里。
本集人物：Rune、Lena、塔楼守卫群像、拾荒者群像
本集场景：干涸航道·沙脊；拖船·驾驶舱；灯塔·底层


【1-1 昏 外 干涸航道·沙脊】
人物：Rune、Lena [VO]、拾荒者群像

△（远景）退潮后的航道摊开成一片碎贝壳与盐壳，拖船斜插在沙里，桅杆上是唯一还在动的东西。
△（近景·跟）Rune 踩过盐壳走到船首，蹲下，用手掌量了一遍龙骨陷进沙里的深度。

Lena（无线电，平，语速偏慢）[VO]：Three barrels. The winch, not the hold.
Rune（低声，说给自己听）：She'll float before I open that door.

【1-2 昏 内 拖船·驾驶舱】
人物：Rune

△（中景）驾驶舱里只有一盏油灯，玻璃上糊着盐；Rune 把绞盘的卡箍拆下来放在桌板上。
△（特写）卡箍内壁的锈一圈套一圈，Rune 用拇指刮了一下，锈粉落在桌板上。

【1-3 夜 外 干涸航道·沙脊】
人物：Rune、Lena、拾荒者群像

△（中景）潮水从航道尽头推上来，探照灯的光沿着水面铺到船身；Lena 把第一根钢索挂上船尾。
Lena（朝沙脊上喊，短）：Now.
```

要点：集头块四件套齐；场标题都是「场号 ＋ 时间 ＋ 内外 ＋ 母场景·子视图」；
人物行只有人名与群像；场外人声标了 `[VO]`；每场都以一个完成状态收尾。

### 11. 常见错误对照

| 错误写法 | 为什么错 | 改法 |
|---|---|---|
| `【1-1 日 外 干涸航道】` | 只有母场景名，分镜会把同一套景重复生成几十次 | `【1-1 日 外 干涸航道·沙脊】` |
| `【1-1 清晨 外 灯塔】` | 时间不在封闭集合里，分光没有依据 | `【1-1 晨 外 灯塔·底层】` |
| `人物：Rune（拖船内）、Lena` | 人物行带中文注释，资产与分镜会认错 | `人物：Rune、Lena`（人在舱内写进场景：`PR-01 拖船·驾驶舱`） |
| `人物：拖船、Rune` | 载具不是人 | `人物：Rune`，船写进场景 |
| `△ Rune 转身。` | 没有结束状态，镜头不知道停在哪 | `△（近景）Rune 转身四分之三停下。` |
| `△（近景·推轨 24mm）……` | 括号里只允许景别（必要时一个运镜词） | `△（近景·推）……` |
| `△（近景）她把刀收回鞘里。` | 说明文字用代词，分镜认错人 | `△（近景）Lena 把刀收回鞘里。` |
| 无线电台词没标 `[VO]` | 配音会按现场口型处理 | `Lena（无线电，平）[VO]：…` |
| 同一场里从夜写到天刚亮 | 一场一个连续时空 | 拆成 `【… 夜 …】` ＋ `【… 晨 …】` 两场 |
| 夜戏通篇没说光从哪来 | 分镜没有布光依据 | 写明实体光源：火／灯／月／炉／焊枪／车灯 |
| 场头写 A 地、正文一直在 B 地 | 场标题与画面打架 | 换场号，或把场头改到正文所在的地方 |
| 画面里出现旗号文字、字幕、水印 | 生成出来会带不可控文字 | 旗号只用图形；字幕与水印一律不出 |

## 剧本之外：项目结构与支持文档

```text
<项目目录>/
|-- 第N集.txt                        正本（一集一文件，纯剧本格式）
|-- <剧名>-全局设定.txt               画风／光色／世界规则／资产命名表／人物／场景／物品／出图提示词
|-- <剧名>-第一季整体大纲.txt          故事引擎／人物弧线／分集地图／集间衔接硬规则／逐日锚点
|-- <剧名>-台词对照本.txt             逐条英文＋中文大意（对账与配音用，脚本生成）
|-- <剧名>-分集场次表.txt             一行一场：排期与资产分派用（脚本生成）
|-- <剧名>-台词中文映射.txt           （可选）新增／改写台词的中文补充表：`集号｜EN｜CN`
|-- <剧名>-交付说明.txt               （可选）包内有什么、本轮改了什么
|-- 交付/                            所有对外交付物：zip、PDF
|   `-- 旧版本/
|-- 审查/                            所有审查记录：第 N 轮 md ＋ 机械校验 json
|-- 备份-<节点>-<YYYYMMDD>/           改稿前快照
`-- 项目开发/                         （可选）选题、决策、制作形态卡等过程文件
```

| 文件 | 职责 | 谁读它 |
|---|---|---|
| `第N集.txt` | 这一集的可拍剧本 | 分镜、资产、配音、演员 |
| 全局设定 | 全剧共用的唯一契约（含资产命名表） | 美术、资产、分镜、写手 |
| 整体大纲 | 这一季为什么这么排（含逐日锚点与集间衔接硬规则） | 统筹、写手、审稿 |
| 台词对照本 | 台词账：与正本一一对应的 `EN｜` / `CN｜` | 配音、审稿、翻译 |
| 分集场次表 | 排期与分派：总览 ＋ 场景使用统计 ＋ 一行一场 | 统筹、资产、分镜 |
| 交付说明 | 这一包是什么、本轮改了什么 | 客户、审查员 |
| 审查记录 | 审到哪一步、还差什么 | 写手、客户 |

命名与别名：支持文档一律 `<剧名>-<类型>.txt`；脚本同时认别名（`分集表`＝`分集场次表`）。
**正本文件名固定** `第N集.txt`，因为分镜系统按文件名排序取集号。

动大稿前先整份拷一份 `备份-<节点>-<YYYYMMDD>/`；旧格式稿另存 `旧格式备份/`，不做就地覆盖。

## 脚本说明

四个脚本都只用 Python 3 标准库，零外部依赖。

| 脚本 | 作用 | 常用参数 |
|---|---|---|
| `short-drama-script/scripts/init_project.py` | 建项目骨架：目录（含 `交付/`、`审查/`）＋ 四份支持文档 ＋ 第一集集头模板；已存在的文件跳过不覆盖 | `--title <剧名>`（必填）、`--english-name`、`--episodes` |
| `short-drama-script/scripts/build_derived_docs.py` | 从正本重建派生件（分集场次表／台词对照本），保留已有中文并列出缺中文条目 | `--check` 只体检不写、`--only sheet\|reference` 只重建一份、`--props a,b` 扩充物件关键词 |
| `short-drama-script/scripts/pack_delivery.py` | 打包到 `交付/`：正本＋支持文档＋`审查/`；显式 UTF-8 文件名标记、逐文件回读比对字节、SHA-256、同名不覆盖 | `--label r2`、`--name`、`--out`、`--no-audit`、`--dry-run` |
| `short-drama-script-audit/scripts/audit_plain_script.py` | 机械校验＋项目与交付检查；有 FAIL 时退出码 1，可直接当门禁 | `--json 审查/机械校验.json`、`--strict`（WARN 也算失败） |

补充中文映射文件（可选）放在项目根目录，文件名 `<剧名>-台词中文映射.txt`，每行一条：

```text
12｜She'll float before I open that door.｜门我不会开，船照样会浮起来。
```

## 审查与结论分级

审查分五类，前四类要逐场读，第五类看目录：

| 类 | 查什么 |
|---|---|
| A 格式与可解析性 | 集头块、场标题（时间／内外／子视图）、人物行写法、说话人是否在人物行、`[VO]`、旧格式残留、台词量、台词账对账 |
| B 连续性 | 数值线（箭／水／弹／人数／天数）、道具线、伤情线、时间线、信息线、道具来源 |
| C 接缝与顺滑度 | 本场落地、下一场接住、时间承载、到场交代、战斗收束、夜戏光源、集间接续 |
| D 台词 | 金句腔、翻译腔、复用、改词后的接话断裂、与动作矛盾、腔调雷同 |
| P 项目与交付 | 支持文档齐不齐、派生件与正本是否脱钩、审查记录是否留档、交付包是否比项目旧 |

结论分四级，交付问题分开给**内容层**与**包层**两个结论：

| 结论 | 含义 |
|---|---|
| `APPROVE` | 机械项全过，四类专项无阻断问题 |
| `APPROVE_WITH_NOTES` | 只有不阻断的改进 |
| `REVISE` | 存在 A／B／C／D 任一类的实质问题 |
| `PROVISIONAL` | 缺关键输入（没有资产表／没有台词账／只有片段），无法完成判断 |

审查记录落 `<项目目录>/审查/`，**每次审查一个新文件，不覆盖旧记录**（格式与状态机见
`short-drama-script-audit/references/review-ledger.md`）。

## 安装 / 同步

仓库是**源**，`~/.codex/skills/` 是安装副本。改完用仓库根目录的脚本对齐：

```bash
./sync.sh              # 仓库 → ~/.codex/skills（装最新版）
./sync.sh --check      # 只比对差异，不动文件
```

手动安装也可以（把两个目录拷进 skills 目录）：

```bash
cp -R short-drama-script short-drama-script-audit ~/.codex/skills/
```

## 标准流程

**新建项目**

```bash
python3 short-drama-script/scripts/init_project.py <项目目录> --title <剧名> --episodes <N>
```

生成目录骨架（`交付/`、`审查/`）、四份支持文档、第一集集头模板；已存在的文件跳过、不覆盖。

**写一集**

先读 `short-drama-script/references/format-spec.md`（格式标准）与
`references/write-checklist.md`（写作自检＋真实事故清单），然后写 `第N集.txt`。
集头块 → 场标题 `【N-M 时间 内／外 场景】` → 场下三件套（人物行／`△` 动作行／对白行）。

**生成派生件（不许手改）**

```bash
python3 short-drama-script/scripts/build_derived_docs.py <项目目录>            # 重建 + 对账
python3 short-drama-script/scripts/build_derived_docs.py <项目目录> --check    # 只体检
```

**审查门禁**

```bash
python3 short-drama-script-audit/scripts/audit_plain_script.py <项目目录>
```

FAIL 不为 0 就不要往下走；审查记录落 `<项目目录>/审查/`，每次审查一个新文件，不覆盖旧记录
（格式见 `short-drama-script-audit/references/review-ledger.md`）。

**交付**

```bash
python3 short-drama-script/scripts/pack_delivery.py <项目目录> --label r1
```

包内显式写 UTF-8 文件名标记（macOS 的 `zip` 默认不打，解压会乱码），写入后逐文件回读比对字节，
输出 SHA-256；同名包不覆盖，自动加序号。

## 维护规则

1. **任何改动都要 commit 并 push 到本仓库**——改 SKILL.md、加 references、改脚本都算；
   不要只改本地安装副本。
2. 改完的顺序：改仓库文件 → `./sync.sh` → 跑校验（脚本自测 ＋ 拿一个真项目
   `audit_plain_script.py` 体检）→ commit ＋ push。
3. 同源副本要一起改：改**格式**时，`short-drama-script/references/format-spec.md`、
   `short-drama-script-audit/references/format-spec.md` 和本 README 的
   [剧本格式](#剧本格式纯剧本格式场次本)章节是同一套规则，三处一起改；
   改**目录结构**时，两份 `project-layout.md` 一起改。脚本会做 hash 比对，漂移会在检查里报出来。
4. 校验脚本依赖 Python 3 标准库，零外部依赖；skill 结构校验可用
   skill-creator 的 `quick_validate.py`（需要 PyYAML）。

## 首次推送 / 日常推送

```bash
# 首次（已配置好 origin 时跳过前两行）
git remote add origin https://github.com/beautyaiClub/short-drama-skills.git
git branch -M main
git push -u origin main

# 日常
./sync.sh && git add -A && git commit -m "docs: 说明改了什么" && git push
```

注意：走 HTTPS 推送时，**fine-grained PAT 必须勾上 Repository permissions → Contents: Read and write**
（只有 read 权限时 `git ls-remote` 能过、`git push` 会报
`403 … denied`，API 侧报 `Resource not accessible by personal access token`）。
推完不要在 `.git/config` 里留 token：用 `credential.helper` 或 `GIT_ASKPASS` 临时提供即可。
